# 货币战争优化版配置

本文对应 `CurrencyWarsPlus` 扩展 **plusv1** 的配置行为，宿主基线为官方 **v2.24.1 / d1fb48a**。扩展开发者：**YukkiSSYB**；感谢 **Shasnow / StarRailAssistant 贡献者**提供基础实现。攻略原作者保留在各 JSON 的 `author` 中。

| 显示名称 | 字段 | 取值及作用 |
| --- | --- | --- |
| 开拓者名称 | `username` | 非空游戏内名称；攻略里的角色统一写“开拓者” |

## 文件格式与角色名

将攻略保存为 UTF-8 无 BOM 的严格 JSON；不含注释、尾逗号或重复键。带中文注释的 [JSONC 填写规范](strategies/货币战争增强版_标准配置填写规范.annotated.jsonc)用于阅读，不能只改后缀就作为正式攻略使用。不要在运行途中修改正在使用的文件。

角色规范名以 [characters.py](characters.py) 为准。`姬子·启行` 与 `姬子`、`银狼LV.999` 与 `银狼`、`火花` 与 `花火` 分别是不同角色。换人时同步核对根名单、阶段、职责、席位、接班、羁绊和装备引用。

## 常用顶层字段

| 字段 | 作用与省略行为 |
| --- | --- |
| `title`、`description`、`author`、`uploader` | 展示与来源信息；保留攻略原作者，扩展适配可单独署名 |
| `share_code` | 游戏内攻略分享码；空字符串不自动导入，不替代本地运营配置 |
| `on_field`、`off_field` | 采购名单，格式为“角色名: 目标星级”；推荐整数 1、2、3 |
| `main_c` | 首次主 C；省略或 `null` 关闭，启用时须在根采购名单定义 |
| `main_c_search_level` | 首次搜索等级，默认 5；持有在备战席不算首次上场 |
| `main_c_search_min_coins` | 首次搜索金币底线，默认 0 |
| `main_c_search_purchase_reserve_gold` | 首次搜索时额外留给购牌的金币，默认 0；刷新和经验保留此金额，需求购牌可使用 |
| `formation` | 阶段阵容、职责、候选席位、羁绊与升级条件；省略或 `null` 沿用基础布阵，没有 `enabled` 字段 |
| `economy` | 新阶段经济；省略、`null` 或 `enabled: false` 沿用旧经济 |
| `opening_policy` | 分别限制开局出售和刷新何时开放 |
| `equipment` | 已上场角色的推荐装备检查顺序和周期；省略不等于禁用装备 |
| `reward_fast_rounds` | 指定奖励快速关卡；省略、`null` 或空列表使用普通流程 |
| `special_events` | 已支持事件的选项关键词和优先级组 |
| `preparation_budget`、`shopping_budget` | 准备与购物的分项动作、次数和时间配置 |

## 采购目标、阶段与职责

根名单定义采购目标，阶段名单定义当前部署目标。目标星级不是买入张数；启用 `formation` 时只使用 1–3 星。阶段的 `requires_stars`、席位候选的 `min_stars` 和 `upgrade_gate.fielded` 定义准入或升级门槛，不自动提高根采购目标；职责缺口可驱动对应候选的采购。

`formation.stages` 为非空数组，按顺序判断；首阶段 `min_capacity` 必须为 0 且没有角色前置条件。人口指普通角色可用名额，已确认、占人口的 NPC 会减少可用容量，因此界面九人口不一定满足 `min_capacity: 9`。各阶段前台 1–4 人，后台受实际槽位及锁定支援限制。`priority` 表示部署顺序，不表示精确格子坐标。

| 阶段或高级字段 | 含义 |
| --- | --- |
| `requires_available` | 已可靠持有，备战席也算 |
| `requires_fielded` | 已可靠上场 |
| `requires_stars` | 已可靠持有指定星级 |
| `roles`、`role_requirements` | 提供者、区域、最低星级与不同角色覆盖数；缺口行为可选 `warn_continue` 或 `block` |
| `traits`、`preserve_traits` | 手工羁绊表及已建立羁绊的保护阈值；不自动查询游戏，不主动要求凑齐 |
| `upgrade_gate` | 从指定等级起，要求上场星级、羁绊或可靠费用满足后才放行常规升级 |
| `assignment_groups` | 在指定区域择优使用一个候选席位，当前 `count` 仅支持 1 |
| `position_rules` | 条件满足后迁移阶段目标的前后台区域，不新增采购目标 |
| `protect_until_fielded` | 接班角色可靠上场后，解除对旧角色的保护 |

席位候选先比较可靠星级，再比较 `rank`；不能仅凭更高 `rank` 用一星替换两星现任。前置条件和保护规则应保持可达，避免要求“先上场才能进入允许上场的阶段”。

## 经济、金币储备与主 C

旧经济字段 `min_coins`、`min_level`、`mid_level` 默认分别为 40、7、7；开启新经济后不参与新经济决策。

启用 `economy` 后，每行阶段包含 `from_battles`、`target_level`、`reserve_gold`，可选 `upgrade_gold`。首行战斗数为 0，后续严格递增；目标等级不能下降。战斗数是已可靠确认结束的真实战斗数，不是循环次数或关卡编号。可靠金币达到 `upgrade_gold` 可提前进入对应阶段，同局阶段不倒退。

记阶段保留金为 R、`economy.purchase_reserve_gold` 为 P：普通需求购牌后保留 R，刷新和买经验后保留 R+P。P 默认 0。首次主 C 搜索改用 `main_c_search_min_coins` 作为底线，并使用单独的 `main_c_search_purchase_reserve_gold` 留购牌金；不叠加常规 P。可靠免费动作不会继续扣余额，其他门槛仍有效。

可选 `economy.all_in_round` 使用 `x-y` 字符串。从指定关卡起，只有证据可靠且足够完成到最终目标的升级时，才启用零保留冲级；该分支可覆盖首次主 C 与常规升级门槛并扩大日常动作额度。奖励快速分支仍仅处理自然页采购。

### 3-7 强制终局运营

可靠确认当前准备关卡恰为 **3-7** 时，对所有攻略生效，不需要开启 `economy` 或 `all_in_round`，也没有攻略开关可关闭。它覆盖日常金币保留、主 C 首次搜索、升级门槛、经济目标等级、开局刷新限制和日常购物额度。

每次先判断能否支付下一整级经验；足够则逐次购买并确认，不足或已满级则零保留购买需求牌和搜牌。不会为了花钱购买无需求角色，也不直接把九级当满级。免费与付费刷新累计最多 80 次，内部恢复不重置，末页继续购牌。

额度耗尽、无可执行动作、格位不足或观察不确定都可能留下金币。终局规则不取消角色目标、人口、职责、羁绊和动作确认要求。

## 开局、奖励回合与装备

`opening_policy.sell_from_round` 与 `refresh_from_round` 使用 `x-y` 字符串，含指定关卡；未知回合仍保持相应动作禁用。禁刷新仍可购买自然页需求牌。首场真实战斗前不购物；未知历史接管不当作首战。

`reward_fast_rounds` 为不重复的关卡数组，只影响列出的关卡。启用条件满足时，只购买自然商店当前页需求牌，不刷新、不买经验，跳过该轮常规水晶、全队扫描、布阵、出售与装备。不要将需要换阵或补装备的普通关卡随意加入；3-7 始终使用强制终局流程。

`equipment` 需要非空 `priority_characters` 和 `others_from_round`，`interval_battles` 默认 2。只处理已上场合格角色，指定关卡前只检查优先名单，之后开放其他角色；首次开放其他角色也可触发检查，因此不是严格固定在第 2、4、6 战检查。推荐装备不能指定逐件配方。仅需间隔时可使用顶层 `equipment_interval_battles`，两处同时填写时必须一致。

## 事件关键词

当前支持“头号玩家、盛会之星、命运卜者、领航员、命运圣杯”等既有事件。`special_events` 的键和值均为字符串。`>` 分隔优先级组，从左到右尝试；同组空格分隔任一匹配词，组内沿用界面顺序，例如：

```json
{"special_events": {"领航员": "护盾 三月七 > 能量 星期日 > 战技点 丹恒·饮月"}}
```

非空关键词均未匹配时，复核后停止本次选择；未配置或空字符串保留末项默认选择。不能存在空优先级组，也不能仅添加未知事件名就获得新事件支持。

## 预算与时间含义

| 对象 | 默认值与边界 |
| --- | --- |
| `preparation_budget` | `seconds: 120`、`actions: 20`、`recoveries: 2`、`move_retries: 1`、`total_seconds: 300`、`field_refresh_seconds: 60`；可省略或 `null` |
| `shopping_budget` | `actions: 60`、`seconds: 90`、`purchases: 60`、`refreshes: 60`、`experiences: 60`；可省略或 `{}`，不能写 `null` |

准备时间及动作值上限为 600；恢复和重试允许 0，其余时间和动作须为正整数。购物 `actions`、`seconds` 为 1–300，分项次数为 0–300。购物总动作包含购买尝试、刷新和买经验；次数按同准备期累计，不因重新开店重置。`all_in` 及 3-7 有各自覆盖规则。

`shopping_budget.seconds` 当前保留兼容读取，**不作为正常购物总时限**。`preparation_budget.total_seconds` 会补偿购物及部分导航耗时，**不等于整个准备页的绝对墙钟上限**。可选 `confirmation_seconds` 当前仅解析校验，尚未接入动作确认时限，不应依赖它调整超时。

## 恢复与任务重建

明确可恢复的流程故障在内层恢复耗尽后，允许同一进程、同一宿主线程串行重建一次任务对象；不创建进程或线程，不重新加载攻略，也不重开当前局。交易证据、稳定准备期、累计动作、等待耗时、经济与装备状态、真实战斗和剩余局数继续沿用。只有新的真实战斗恢复外层重建额度。

重建不能补造购前基线或已缺失的观察事实。停止、配置错误、终局或存档故障不进入此恢复。程序完全关闭后的简略检查点恢复，与这种完整上下文交接并不等价。

## 适用范围、数据和许可

普通出战和超时收尾使用共同未决输入门槛；奖励快速流程仅可延后已确认采购的整理。命运卜者交接后重新认证页面；银狼费用补读按稳定准备期只消耗一次，计时补偿和对象重建不重授。

局部事件优化限已确认的领航员和盛会之星增益；未知奖励仍可能使全场观察失效。血量读取缺失、冲突或页面已跳转时保留未知，单次同步 OCR 仍可能影响停止响应。

运行数据位于宿主应用数据目录下 `currency_wars_plus/`，包括 `state/`、`logs/` 和 `diagnostics/`。同时运行多个实例可能互相覆盖会话，分享诊断前需筛选个人信息。
