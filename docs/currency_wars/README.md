# 货币战争配置与使用说明

货币战争支持主 C 首次上阵、分阶段阵容、经济策略、装备检查和中断恢复。本次改动保留原有三份攻略，新增六份攻略，并将流程和识别改进合并为一次更新。

## 选择和填写攻略

从源码运行的环境要求、依赖安装和启动方式见[贡献指南](../../CONTRIBUTING.md)。识别校准以 **1920×1080** 的游戏画面为基准，执行任务时请避免其他键鼠操作。

1. 在货币战争设置中选择已有攻略，或复制本目录的 [strategy_template.json](strategy_template.json) 填写自己的攻略。
2. 参照 [strategy_template.annotated.jsonc](strategy_template.annotated.jsonc) 修改字段。JSONC 含注释，仅用于阅读；程序加载的文件必须是合法 JSON，使用 UTF-8 编码，建议不带 BOM。
3. 将新攻略放入实际运行后端的 `tasks/currency_wars/strategies/`。从本源码仓库启动时，即为项目根目录下的该路径；也可使用程序提供的攻略文件导入功能。
4. 刷新攻略列表或重新打开助手，选择该攻略，再启动货币战争任务。文档目录中的模板不会自动加入攻略列表。

角色名以 [characters.py](../../tasks/currency_wars/characters.py) 为准。`银狼LV.999` 与 `银狼`、`火花` 与 `花火` 是不同角色。更换角色时，需要同步修改根名单、阶段名单、职责和保护规则中的引用。分享码用于导入游戏内攻略，本地采购和布阵仍按 JSON 配置执行。

## 常用字段

| 字段 | 用途 |
| --- | --- |
| `title`、`description`、`author`、`uploader` | 攻略展示信息；不填写的署名可使用空字符串 |
| `share_code` | 游戏内攻略分享码；留空表示不自动导入 |
| 根级 `on_field`、`off_field` | 角色采购名单及目标星级；新阵容配置使用 1、2、3 星 |
| `main_c`、`main_c_search_level` | 日常运营首次搜索主 C 的等级及其上阵确认规则；`main_c: null` 关闭 |
| `formation` | 阶段阵容、上场条件、职责、候选席位、羁绊保护和前后台迁移 |
| `economy` | 分阶段目标等级、金币保留、阶段切换和可选 `all_in_round` |
| `opening_policy` | 从指定、已确认的关卡起允许出售或刷新 |
| `equipment` | 装备检查的角色优先级、其他角色开放回合和战斗间隔 |
| `preparation_budget`、`shopping_budget` | 布阵、恢复和日常购物的操作预算 |
| `special_events` | 已支持特殊事件的选项关键词 |

完整字段、取值范围、默认值和组合条件见注释模板。配置校验会拒绝部分未知字段、无效角色引用和不成立的条件；请使用已有字段定义。

## 阵容与采购

根级名单决定整套攻略的采购目标，涵盖正式角色和过渡角色。开启 `formation` 后，阶段中的前后台名单决定当前部署区域，`priority` 决定人口不足时的部署优先级。它们不指定精确格子坐标。

阶段按配置顺序判断，首阶段从 `min_capacity: 0` 开始。人口门槛使用普通角色可用名额，即游戏人口上限减去已确认、占人口的 NPC；部署时仍按游戏总人口上限防止超员。锁定备战格不能作为空位或可操作角色，后台支援需要确认身份后才能参与占位判断。

角色目标星级与阶段准入条件需要分别填写。根名单的星级驱动采购；`requires_stars` 和席位候选的 `min_stars` 只定义准入条件，不会自动提高采购目标。职责缺口则可以驱动正式或过渡候选的采购。开启职责、羁绊保护或接班保护时，只有可靠确认的角色和星级参与判断，尚未完成的拖动不算已经上阵。

购买采用同页连续采购及数量缓存，合成、满席、布局变化、事件或观察冲突会触发重新核实。买到主 C、需要补职责或需要腾出格位时，购物可交回整备流程，完成布阵后继续。出售批次在确认部分成交后耗尽预算时，会保留已确认结果，随后重新观察剩余角色。

## 日常经济与兼容行为

未设置 `formation`、未启用 `economy` 或未设置 `equipment` 时，对应部分继续使用原有流程。原有三个 `template` 的内容保持不变，可继续选择使用。新增攻略中的策略模块按各自 JSON 启用。

设置主 C 后，日常运营达到搜索等级时，会先搜索并确认主 C 合法上阵，再继续升级。备战席持有不算上阵；首次确认也不要求先达到采购目标星级。攻略可通过 `formation.upgrade_gate` 增加星级、羁绊或实际费用等升级条件。

`economy.enabled: true` 启用新的经济阶段，旧字段 `min_coins`、`min_level`、`mid_level` 不再参与新经济决策。阶段按已确认战斗数或可靠金币条件推进；续跑时重新观察现场，并核对保存的阶段。`reserve_gold` 是阶段保留金币，`purchase_reserve_gold` 是额外留给买牌的金额：日常刷新和买经验需保留两者之和，需求买牌可使用额外的买牌储备。

可选的 `economy.all_in_round` 用于指定回合的全额运营，具体触发条件见注释模板。日常购物预算在同一备战期间累计使用，重新打开商店不会重置；配置的全额运营分支可能提高预算。`shopping_budget.seconds` 保留作为历史兼容字段，当前正常购物不以它限制总时长。

### 3-7 终局运营

**可靠确认当前为 3-7 备战阶段后，程序对所有攻略执行强制终局运营。** 该规则无需启用 `economy`，优先级高于主 C 首次上阵规则、升星升费门槛、配置目标等级、金币保留及日常购物预算。

1. 读取并确认当前等级、金币和经验进度。金币足够完整升到下一级时，逐次购买经验并确认结果；升完一级后重新判断。
2. 金币不足以完整升级，或可靠确认已经满级时，按攻略需求买牌和搜牌，保留金币降为零。不会为了消费金币购买不需要的角色，也不会将九级直接视为满级。
3. 付费和免费搜牌输入合计最多 **80 次**。确认失败的搜牌输入也计入次数，同一备战期间的内部恢复不会重新获得额度；第 80 次刷新后的页面仍会采购需求牌。

这项规则可能留下金币。达到搜牌上限后会停止刷新；仅剩 1 金币且当前没有可买的 1 费需求牌时也会停止。格位不足、待确认交易或其他操作问题可能要求先整备或恢复。关卡、经验、等级或交易证据不可靠时进入有边界的恢复流程，不能把未知状态当作消费完成或直接出战。

## 装备、恢复与适用范围

装备策略安排已上场角色的检查顺序和检查间隔，实际分配使用游戏推荐操作。配置不能保证指定装备词条、逐件合成顺序、角色具体形态或精确站位；攻略中的角色和生效区域也需要结合当前游戏版本核对。

阶段切换、进战斗、结算、补给选择和拖动会结合当前画面确认结果。恢复使用重试次数、操作次数和时间边界；达到边界后停止或报错。会话检查点保存策略指纹、战斗确认和经济阶段等信息，继续挑战时重新观察现场，不直接重放历史待确认动作。更换攻略、损坏或不匹配的检查点不能当作当前棋盘的可靠依据。

本次提供 1920×1080 校准和离线回归测试，其他窗口尺寸不属于本次验证范围。离线检查能验证配置、流程保护和识别机制；不同游戏版本下的角色形态、装备效果及完整自动运行仍需实机核对。本次没有启动游戏进行端到端验证，也不提供胜率或收益保证。
